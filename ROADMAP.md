# StationSpeed — состояние и план

Множители скорости станций. Тикающие станции — деление времени на продукт в
`Awake` (действует у владельца); бочка и растения — одноразовый сдвиг метки
старта, чтобы ванильный клиент считал готовность так же.

Текущая версия: **0.1.0** — собрана и проверена `check-refs.ps1`, в игре ещё
не запускалась. Игра: Valheim 1.0.x (network version 40), BepInEx 5.4.23.5,
Harmony 2.9.

---

## Сделано

- [x] **Smelter** (плавильня, доменная, угольная, прялка, мельница, очиститель
      эйтра, прочее) — `m_secPerProduct /= k` в постфиксе `Awake`.
- [x] **CookingStation** (жаровни, печь, прочее) — `m_cookTime /= k` у каждой
      конверсии; подгорание в игре — `2 × m_cookTime`, масштабируется вместе.
- [x] **Beehive**, **SapCollector** — `m_secPerUnit /= k`.
- [x] **Fermenter** — prefix/postfix `RPC_AddItem`: если метка `StartTime`
      изменилась (закладка принята) и мы владелец — сдвиг на `D − D/k`.
- [x] **Plant** — prefix/postfix `Awake`: если `plantTime` был 0 и появился
      (только что посажено, мы владелец) — сдвиг на `T − T/k`, где `T` —
      `GetGrowTime()` через рефлексию (засеян по растению, у всех клиентов
      одинаков).
- [x] Множитель на тип + `ByPrefab` с приоритетом; консоль `stationspeed status`.
- [x] Сборка `build.ps1`, проверка `check-refs.ps1` (типы, члены, рефлексия,
      цели `[HarmonyPatch]`).

## Проверить в игре перед следующими задачами

- [ ] Порядок `Awake`: `ZNetView.Awake` раньше `Plant.Awake` (игра сама на это
      полагается), иначе префикс увидит `null` ZDO и сдвига не будет.
- [ ] Бочка при `k=2`: у второго клиента (без мода) статус «готово» наступает
      через `D/2` и тап срабатывает.
- [ ] `RPC_AddItem` не меняет `StartTime` при отказе (полная бочка, нет крыши) —
      иначе двойной сдвиг. По IL — не меняет, но проверить.
- [ ] Растения: `GetGrowTime()` действительно одинаков на клиентах (засеян
      `m_seed` из ZDO) — сравнить `Debug`-лог с двух клиентов.
- [ ] Плавильня при смене владельца посреди партии: накопитель в ZDO общий,
      скорость меняется на скорость нового владельца — ожидаемо, но убедиться,
      что ничего не сбрасывается.
- [ ] `CookingStation.m_conversion` у клона — свои объекты, не общие с
      префабом (иначе деление накопится). По устройству Unity — свои.

## Дальше

- [ ] **Сдвиг с хоста для чужих закладок.** Хост хранит все ZDO мира. Раз в
      несколько секунд просматривать ZDO префабов `fermenter` и растений
      (как LivingMap читает `ZDOMan.m_objectsByID`): у кого `StartTime`
      свежий и нет нашей отметки (свой ключ в ZDO, ванилла его не трогает и
      сохраняет) — сдвинуть и отметить. Тогда бочка, заложенная игроком без
      мода вдали от хоста, тоже ускоряется, и никто ничего не ставит.
- [ ] **Синк конфига** между модовыми клиентами (ServerSync / Jotunn), чтобы у
      всех владельцев были одни множители, иначе скорость станции зависит от
      того, кто рядом стоит.
- [ ] **Владение станциями на хосте** для тикающих станций рядом с хостом —
      общий приём с BossMeter; вынести в отдельный хост-мод.
- [ ] Отдельные множители для **грядок и саженцев** (`Plant` не различает;
      по префабу `sapling_*` / `*Sapling*` против остального).
- [ ] Печь: `m_secPerFuel` — расход топлива по времени; при ускорении
      готовки топливо тратится за то же время — решить, масштабировать ли.
- [ ] Ветряная мельница и прялка зависят от ветра/скорости вращения
      (`Windmill`): проверить, что `m_secPerProduct` там вообще главный
      ограничитель.
- [ ] Иконка Thunderstore — сейчас заглушка, сгенерированная скриптом.

## Идеи

- Команда `stationspeed rescan` — применить множители к уже загруженным
  станциям без перезахода (пересчитать поля по префабу).
- Показывать в hover-тексте станции действующий множитель.
